Better filters from messy product data

Customers weren't using filters on large category pages, and many who did left soon after. The obvious fix was a new filter design. The real problem was the data behind it.

Three systems, three spellings

Filter values came from ERP, CMS and the shop system, and the same attribute was often defined three ways. A filter is only as good as the data behind it.

A bar before a filter appears

Each category got a minimum coverage for every filter. Filters that couldn't meet it were removed, which was the hardest conversation: it looked like shipping less.

Three paths we considered

  • Redesign the filter UI

    Fastest to show, but a better interface on top of the same gaps.

  • Clean the whole catalog first

    Right in principle, but months before any customer saw a change.

  • What we did

    Fix category by category

    Ship each category once its data meets the bar, starting with the highest traffic.

What I'd do differently

I'd set up a control group from the start. Comparing against the previous period makes seasonality harder to rule out. I'd also bring merchandising in earlier, since they knew which attributes customers shopped by long before our data showed it.
